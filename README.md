# translator — Quickshell popup for ii/dots-hyprland

Popup перекладач (uk↔en) і voice-input під Hyprland + Quickshell,
візуально узгоджений з [end-4/dots-hyprland](https://github.com/end-4/dots-hyprland)
("ii"). Живе в окремому Quickshell-конфізі (`qs -c translator`) — **не
форк і не патч самого `ii`**, тож апдейти `ii` ніколи його не зачеплять.

## Що вміє

- Layer-shell popup (Overlay), floating, не штовхає інші вікна.
- Напрямок перекладу стежить за поточною розкладкою клавіатури
  Hyprland (uk↔en), включно зі зміною розкладки прямо під час набору.
- Переклад: пробує Google Translate (gtx, безкоштовний) першим; якщо
  той відповідає 429 (rate-limit) — автоматично перемикається на
  локальний LibreTranslate. Бейдж під полем показує, який бекенд зараз
  активний.
- Voice input: тап на мікрофон → миттєвий запис (не чекає завантаження
  моделі) → авто-стоп по тиші → розпізнаний текст сам з'являється в
  полі вводу → далі йде в переклад тим самим шляхом, що й набраний
  текст. Живий бар-візуалізатор гучності під час запису.
- `Enter` → копіює переклад і вставляє в поле, з якого був викликаний
  попап (`wl-copy` + `wtype`). `Escape` → закриває без вставки.
- Кольори читаються напряму з живого matugen-палітри `ii` — тема
  оновлюється сама при зміні шпалер, без залежності від внутрішніх
  файлів `ii`.

## Швидкий старт (на новому сетапі з ii)

```bash
git clone <this-repo> translator && cd translator
./scripts/install.sh
```

Скрипт перевірить залежності, скопіює конфіг у
`~/.config/quickshell/translator/`, підніме Python venv для STT.
Що робити далі — скрипт сам підкаже в кінці (шорткат, тест запуску,
опційно LibreTranslate).

## Архітектура

### Дві незалежні резидентні частини

1. **Сам попап** (`qs -c translator`) — легкий, стартує миттєво,
   тримається живим постійно (перемикається `ipc call translator
   toggle`, а не перезапускається щоразу).
2. **STT-демон** (`stt_daemon.py`) — важчий (faster-whisper `medium`,
   ~1.3GB RAM), тому має власний, окремий життєвий цикл:
   - **Pre-warm при відкритті попапу**, а не при тапі на мікрофон —
     між відкриттям вікна й реальним тапом завжди є природна затримка
     реакції людини (сотні мс — секунди), і зазвичай цього досить,
     щоб модель встигла довантажитись у фоні непомітно.
   - **Запис і завантаження моделі — незалежні.** Тап на мікро стартує
     `pw-record` одразу, незалежно від того, чи модель уже готова.
     Якщо модель ще вантажиться на момент, коли ти замовк — демон
     просто чекає (`WAITING_MODEL`) решту часу довантаження, а не весь
     час заново.
   - **Keep-alive TTL замість миттєвого вивантаження.** При закритті
     попапу модель не вивантажується одразу — стартує таймер (45с за
     замовчуванням). Якщо відкрив попап знову протягом цього вікна —
     модель вже готова, миттєвий відгук. Якщо ні — вивантажується,
     звільняючи RAM.
   - Аудіо ніколи не пишеться на диск — `pw-record` виводить сирий PCM
     напряму в stdout, демон акумулює його в `bytearray` в пам'яті.

### Протокол STT-демона (stdin/stdout, по рядках)

```
stdin  START            -> старт запису, авто-детект мови
stdin  START:<lang>     -> старт запису з підказкою мови (напр. START:uk)
stdin  STOP             -> ручний форс-стоп запису (фолбек, якщо VAD не спрацював)

stdout LOADING          -> модель почала вантажитись у фоні
stdout MODEL_READY      -> модель довантажилась (інформаційно)
stdout LISTENING        -> йде запис
stdout LEVEL:<0.0-1.0>  -> грубий RMS-рівень гучності (для бар-візуалізації)
stdout PROCESSING       -> запис зупинено, йде транскрипція
stdout WAITING_MODEL    -> (рідко) договорив раніше, ніж довантажилась модель
stdout RESULT:<text>    -> фінальний розпізнаний текст
stdout ERROR:<msg>      -> щось пішло не так, демон лишається живим
```

### Детекція тиші (VAD)

Без сторонніх VAD-бібліотек — просто поріг RMS-гучності
(`SILENCE_RMS_THRESHOLD` у `stt/stt_daemon.py`). Простіше і не тягне
залежностей (спершу був `webrtcvad`, але той зламався через видалення
`pkg_resources` з нових версій `setuptools` — простіше було прибрати
залежність зовсім, ніж гнатись за версіями).

## Налаштування під себе

| Що | Де | За замовчуванням |
|---|---|---|
| Поріг тиші (STT) | `stt/stt_daemon.py` → `SILENCE_RMS_THRESHOLD` | `0.02` |
| Скільки тиші треба, щоб зупинити запис | `stt/stt_daemon.py` → `SILENCE_TAIL_MS` | `800` мс |
| Розмір STT-моделі | `qs/shell.qml` → `command` у `Process { id: sttProc }` | `medium` |
| Keep-alive для STT (скільки тримати модель після закриття) | `qs/shell.qml` → `sttKeepAliveTimer.interval` | `45000` мс |
| Дебаунс перекладу | `qs/shell.qml` → `debounce.interval` | `550` мс |
| Шлях до палітри кольорів ii | `qs/Colors.qml` → `colorsPath` | `~/.local/state/quickshell/user/generated/colors.json` |
| Позиція попапу | `qs/shell.qml` → `anchors`/`margins` у `PanelWindow` | знизу, `margins.bottom: 96` |

## Відомі обмеження / що свідомо не зроблено

- **Транскрипція пакетна, не стрімінгова.** Аудіо накопичується в
  пам'яті, транскрибується одним шматком після того, як VAD визначив
  паузу — а не інкрементально по 100-250мс під час самого мовлення.
  Справжній стрімінг дав би майже нульову затримку фінального
  результату, але вимагає суттєво іншого пайплайна (chunked-інференс,
  часткові гіпотези, що переглядаються по мірі надходження контексту).
  Поточна схема вже ховає більшість затримки за рахунок pre-warm +
  паралельного завантаження моделі під час запису — для коротких фраз
  цього вистачає.
- **Пробний запит до Google при кожному відкритті попапу** (для вибору
  бекенду перекладу) витрачає один запит із того ж ліміту, який ми
  намагаємось обійти. Некритично для звичайного використання, але
  варто мати на увазі.
- **`ii`-специфічні шляхи не гарантовано стабільні між версіями `ii`.**
  Шлях до `colors.json` перевірявся на конкретній інсталяції — якщо
  твоя структура тек інша, `install.sh` про це попередить, але
  виправляти шлях у `qs/Colors.qml` треба вручну.

## Структура репозиторію

```
qs/                    — сам Quickshell-конфіг (те, що йде в ~/.config/quickshell/translator/)
stt/                    — STT-демон + Python-залежності
hypr/                   — приклад шорткату для ~/.config/hypr/custom/keybinds.lua
scripts/install.sh      — автоматизована установка на новому сетапі
docs/                   — детальні інструкції (LibreTranslate, тестування STT-моделей)
tools/                  — окремий CLI-скрипт для ручного тестування STT-моделей поза віджетом
```
